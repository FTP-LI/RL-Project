# XGO-Duck 项目约定

- 当前目标：训练与新增仿真暂停，现有仓库的main只交付可复现工程、关键权重、评估与代表性媒体，完整过程留在本机。原厂套机首次部署、机械中位、IMU、站姿和飞智黑武士4Pro在现场逐项验收后，再继续训练。九类动作与低摩擦续接点保存在当前目标中。
- 环境安装和部署在用户可见的终端或应用窗口执行。训练的 VS Code 终端可选。训练启动前须验收用户可打开的运行中观察入口，持续保存进度、曲线、真实录像、命令日志和退出状态，并用同一运行编号关联文档。只读检查和文档编辑可用普通工具。
- 用户代理会自动切换节点；网络中断后先检查现有进程和缓存，避免并行重复安装。可见终端集中在一个窗口，完成的本任务窗口及时关闭，不堆积终端。
- 桌面操作保持用户现有窗口大小、位置和布局。按用户最新要求，助手自行激活或恢复原 VS Code 并选择已配置的任务；不最大化、拖动或调整窗口、面板大小。
- 用户要求优先使用清华等镜像源。保持官方依赖版本与哈希，下载地址调整单独留档；不得因换源重新求解出不同依赖来冒充官方复现。
- 每次安装保存命令、时间、输出、退出码及结论；关键界面可截图，截图不能替代日志和数值验证。
- `official_resources/` 是原始归档，不直接修改，不在其中安装依赖或运行训练；固定来源见 `official_resources/source_manifest.json`。
- 全流程主报告以 `docs/reports/development_report.md` 为入口，持续更新环境、训练、修改效果、截图/视频和真机标定；项目路线参考 `docs/development_roadmap.md`，现有接口研究保留在 `docs/rl_deployment_plan.md`，实际状态以 `project.json` 与 `records/` 的证据为准。
- 文档放 `docs/`，可执行辅助脚本放 `scripts/`，实验定义放 `configs/experiments/`，执行记录放 `records/`，运行副本与缓存放 `workspace/`，模型交付包放 `artifacts/`。只创建实际需要的目录。
- Linux 训练需使用 WSL 的 Linux 文件系统时，只使用专属 `~/XGO-Duck/`，在记录中登记与本项目的对应关系；可复现配置、脚本和摘要仍保存在本目录。
- 既有用户改动必须保留；不修改兄弟项目。大模型、虚拟环境、下载缓存和训练日志不得未经检查加入 Git。
- 短训练只证明流程可运行；实机部署、稳定行走和改进效果各自需要独立证据，不得相互替代。

- 每次收到新需求，先更新 `docs/current_goal.md` 与 `project.json` 中的目标、范围及验收条件，再执行对应工作；保持既有未完成目标。
- 录像长度按动作动态安排，配置见 `configs/environments/action_recording.json`，新入口使用 `scripts/training/action_video.py:ActionVideo`。起身/滚翻从 episode 起点录到终点（起身训练8s、评估11s；滚翻读实际时长）；行走/站立4s，连续切换录声明的完整序列。约180s到期时等待动作起点，不在中途截取；自动重置前保存终态，不为录像追加物理步。异常片段明确未完成。旧冻结录像器和原片不改，新状态回放单列来源。
- 新训练的执行与观察要求以 `configs/experiments/motion_curriculum.json` 和开发路线为准。默认间隔录制真实动作，保留曲线和日志；同一对照的观察设置须匹配。已冻结任务的 `training_display.json`、`display_preferences.py` 及启动条件随原协议核验。

- 最新训练方向以 `docs/current_goal.md`、`configs/experiments/motion_curriculum.json` 和主报告的当前进展、分阶段训练策略为准：覆盖九类动作，按 S0–S6 及其子阶段推进。用户于 2026-11-02 授权开始执行；先完成 S1，真机部署后置。逐次历史移至 `docs/reports/development_history.md`，不能据旧状态自动恢复学习。S0 离线核验与真实运行验收分别记录。
