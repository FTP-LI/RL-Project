## Archive inventory

- [source_manifest.json](source_manifest.json): repository URLs, selected refs, full commits, tree IDs, local paths, archive sizes and hashes, and validation results.
- [snapshots.sha256](snapshots.sha256): SHA-256 checksums for all four ZIP snapshots, with paths relative to this folder.
- `manifests/*.files.json`: SHA-256 and size for every file in each archived source tree; Git administrative files are excluded.
- `snapshots/*.zip`: source trees generated by `git archive`, named with source, archive date and commit prefix. ZIPs preserve source content but do not contain Git history.

The three source repositories, extracted media preview and ZIPs are deliberately ignored by the parent RL-Project repository to avoid copying upstream history and large CAD/mesh assets into it. The indexes, manifests, checksums and project notes can be committed normally. **Pushing RL-Project alone does not back up these source directories or ZIPs.** Copy `snapshots/` and the manifests together to external storage for an offline backup.

The source links below and in the project notes point to the exact archived commits on GitHub. Local source directories use the archive-entry names listed above; restore them with the instructions below when working from a fresh RL-Project clone.

On 2026-10-28, the file manifests were normalized to UTF-8 with LF line endings for Git portability, and their own hashes in `source_manifest.json` were updated. Individual source-file hashes, pinned commits and snapshot hashes were unchanged. Research and snapshot dates remain 2026-10-25.

No upstream source was edited. No training, dependency installation, firmware flashing, robot connection or motor test is implied by archive verification.

## Recreate Git checkouts on another machine

From this folder, with Git installed, the following PowerShell snippet reads the pinned versions from the manifest. Use it only when the destination directories do not already exist; it intentionally refuses to overwrite them.

```powershell
$archiveManifest = Get-Content -Raw -LiteralPath '.\source_manifest.json' | ConvertFrom-Json
foreach ($source in $archiveManifest.sources | Where-Object { $_.kind -eq 'git_checkout' }) {
    if (Test-Path -LiteralPath $source.local_path) { throw "Destination already exists: $($source.local_path)" }
    git -c core.autocrlf=false clone --no-checkout $source.repository_url $source.local_path
    if ($LASTEXITCODE -ne 0) { throw 'Clone failed' }
    git -C $source.local_path checkout --detach $source.commit
    if ($LASTEXITCODE -ne 0) { throw 'Pinned checkout failed' }
    git -C $source.local_path fsck --full
    if ($LASTEXITCODE -ne 0) { throw 'Git object verification failed' }
}
```

For the media preview, the simplest offline restoration is to verify its ZIP hash against `snapshots.sha256` and extract it here; it already has a `runtime_media_preview/` prefix. To regenerate it from the runtime Git checkout:

```powershell
git -C xgoduck_runtime_arduino archive --format=zip --prefix=runtime_media_preview/ -o ../runtime_media_preview.zip 44b2ac852cc3b03aca0de33996a6b4ff3cd0cab4
Expand-Archive -LiteralPath runtime_media_preview.zip -DestinationPath .
```

Use a fresh destination for extraction. Network restoration depends on upstream retaining the pinned objects; the verified local ZIPs provide an independent tree backup. Preserve the existing dated snapshot when refreshing sources, and regenerate provenance and hashes for the new version.
