# H7MS-Core-A1阶段计划

Core-A1硬件可与XGO Lite2原厂系统、数字孪生和RL工作并行，但不能要求机器人项目等待自研板。每个阶段都有可回退结果。

状态盘点（2026-09-11）：本目录交付物仍为设计文档，H0进行中且未验收；H1～H8尚无对应工程或验证证据归档。下列内容是阶段计划，不表示已完成。实时进展统一维护在[项目状态与待办](08_项目状态与待办.md)。

## 阶段H0：需求与接口冻结

- 在CubeMX复查`STM32H743VIH6`完整引脚、时钟和DMA。
- 明确是否维持BGA100封装；若更换料号/封装，同步修订引脚、电源、PCB和接口映射。
- 关闭RGB与IMU加热共用TIM8的配置问题，不能只检查GPIO是否重叠。
- 冻结核心板尺寸、板对板连接器、安装方向和机械高度。
- 定义核心板电源、安全、USB、UART、CAN、I²C、SPI和SDMMC接口契约。
- 冻结J1/J2逐Pin定义、底板5V预算和预留脚纪律。
- 将XGO专有的收发器、接插件和执行器电源放在底板。

完成标准：引脚文档、原理图接口表和机械约束逐项对应，TBD有明确验证方法。

## 阶段H1：核心板原理图与PCB

评审顺序：

1. MCU电源、VCAP、VDDA、PDR_ON和去耦。
2. 8 MHz有源HSE、LSE、NRST、BOOT0和SWD。
3. 底板5V/USB5V电源选择、3.3V电源和防反灌。
4. 板载IMU、加热、QSPI、TF、RGB和蜂鸣器。
5. 板对板接口和安全默认状态。
6. BGA扇出、层叠、回流路径和测试点。

首批只生产小数量验证板。完成标准为DRC、BOM、坐标、装配说明和评审记录可复现。

## 阶段H2：核心板Bring-up

```text
短路与阻抗检查
→ 限流分电源上电
→ NRST/HSE/SWD
→ 最小固件
→ USB
→ IMU
→ IMU加热与NTC保护
→ QSPI
→ TF卡
→ RGB/蜂鸣器
→ 板对板接口电平
```

每一步保存电压、电流、波形、固件版本和结论。核心板故障时不连接XGO底板或舵机。

## 阶段H3：BSP与安全框架

- 单调时钟和统一时间戳。
- USB帧协议、CRC、序号和超时。
- 底板EEPROM识别和能力表。
- `SAFE_OFF → INIT → READY → ACTIVE → FAULT`状态机。
- ESTOP、电源、底板故障和通信看门狗。
- 双分区或可恢复升级、故障日志和产测固件。

完成标准：无执行器时可通过故障注入验证全部状态转换。

## 阶段H4：XGO协议与电气测量

- 高阻监听CM4与原装下位机通信。
- 高阻监听原装下位机与舵机通信。
- 测量总线电平、方向、波特率、帧间隔和负载。
- 建立舵机ID、命令、反馈与校验字典。
- 测量电池和舵机电源峰值、跌落与启动浪涌。

完成标准：底板收发器、电源监测和线束定义有实测依据。

## 阶段H5：H7MS-XGOBase-A1

- 实现可配置半双工UART收发和默认高阻。
- 原装线束通过转接件接入，不剪断不可恢复线束。
- 实现电池电压、电流、执行器电源开关、保险和急停。
- 保留原厂控制板与Core-A1物理互斥选择。
- 单备用舵机完成只读、位置、停止、卸载和故障测试。

完成标准：台架连续运行无总线争用、异常复位和失控输出。

## 阶段H6：真机分级接管

1. 只读旁路监测。
2. 单腿悬空控制。
3. 四腿悬空控制。
4. 支撑架站立。
5. 地面低速运动。
6. 机械臂与夹爪。
7. 上位策略部署。

每一级比较原厂链与Core-A1链的位置、时延、错误恢复和安全行为。前一级未通过不得进入下一级。

## 阶段H7：本地策略部署

- RTX 3080上训练并只导出Actor网络。
- 使用STM32Cube AI Studio生成并分析H7推理代码。
- 完成PC/H7固定样本数值对齐、最坏耗时和内存测试。
- 策略输出通过限位、变化率、姿态、电源和通信安全层。
- 按回放、悬空、支撑架、低速地面的顺序验证。

完成标准：策略异常或超时可确定性回退，不能绕过Core-A1安全状态机。

## 阶段H8：平台冻结

- 冻结硬件版本、BOM、生产资料和固件发布版本。
- 发布上位机SDK、协议文档、校准格式和故障码。
- 保存原厂恢复方案和线束图。
- 将尚未验证的CAN、外部编码器或FOC能力保持为扩展，不写入首版完成声明。
