# 阶段4：H7MS-Core-A1接管

目标是用`H7MS-Core-A1`与`H7MS-XGOBase-A1`逐步接管实时控制，同时保留原厂控制板作为参考和恢复路径。

## 1. 接管原则

- 先监听，再旁路，再单舵机，最后全身。
- 原厂板与Core-A1不能同时主动驱动舵机总线。
- 上位命令与关节反馈必须带序号和时间戳。
- Core-A1失联、过流、过温、IMU异常或急停时撤销执行器使能。
- 每一步都能恢复到原装线束和原厂系统。

## 2. 四阶段接管

### 4A：CM4—原厂下位机协议复现

使用官方协议和高阻监听建立完整命令字典，复现读取、停止、卸载和低速关节命令。Core-A1此时不连接舵机总线。

### 4B：舵机总线侦察

逻辑分析仪监听原厂下位机与舵机：

- 电平、波特率、半双工方向和帧间隔。
- 舵机ID和分组。
- 单关节/批量位置命令。
- 角度及可能存在的速度、电流、温度反馈。
- 释放、锁定、PID或限位配置。

未知写命令不得在整机总线上试验。

### 4C：单舵机台架

使用备用舵机、限流电源和独立线束验证Core-A1驱动：Ping、只读状态、小角度位置、停止、卸载、故障恢复。记录示波器波形和总线占用率。

### 4D：整机接管

按单腿悬空、四腿悬空、支撑架站立、低速地面和完整任务逐级验证。机械臂和夹爪最后接入，避免同时引入两类机构风险。

## 3. Core-A1职责

- 统一单调时钟和微秒级时间戳。
- IMU采样和基础状态估计。
- 关节总线轮询、批量写入和错误统计。
- 位置目标插值、限位和变化率限制。
- 上位机命令超时和硬件看门狗。
- 电池电压、电流、温度和电源状态管理。
- `SAFE_OFF → INIT → READY → ACTIVE → FAULT`状态机。
- 原始状态日志、故障快照和产测模式。

## 4. 上位机接口

首选USB设备接口作为高速可靠链路，UART8保留为启动日志和维护通道。协议固定包含：

| 类别 | 必备字段 |
| --- | --- |
| 命令头 | 版本、类型、长度、序号、主机时间 |
| 动作 | 模式、关节目标、速度限制、有效期 |
| 状态 | H7时间、关节状态、IMU、电源、温度、错误位 |
| 安全 | 使能、停止、急停确认、故障复位条件 |
| 诊断 | 丢包、CRC错误、超时、舵机离线和循环抖动 |

协议版本不匹配时保持安全状态，不能尝试兼容猜测。

## 5. 一致性测试

同一组受限命令分别通过原厂链和Core-A1执行，比较：

- 关节最终位置误差。
- 命令到反馈延迟和抖动。
- 丢包与舵机离线恢复。
- 上位机断联后的行为。
- 急停和电源故障响应。
- 10分钟连续动作后的温度和错误数。

Core-A1只有在安全行为不弱于原厂链、数据频率和确定性明显改善后，才成为默认控制链。
